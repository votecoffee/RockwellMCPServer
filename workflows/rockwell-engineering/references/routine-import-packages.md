# Routine dependency packaging

Discover and describe `studio_prepare_routine_import_package` at the current Logix extension generation, then use its apply channel. It creates artifacts only; the shared service owns packaging. Inputs are pinned `source:{projectId,sha256}`, `baseline:{projectId,sha256}`, exact `programName`/`routineName`, optional `prerequisiteTags:[{name,scope:"program"|"controller"}]`, and `mode`.

`tag_definition_free` is the default fallback: a full readable RLL/ST routine with context names and no Tag/Tags or saved-value XML. Review `requiredTags.createBeforeImport`, create and verify only missing tags with their exact scope/type/dimensions/initial data, and preserve existing values. The separate manifest preserves all supplied new-tag Data representations without numeric conversion. Selected tags already present in the baseline are rejected; missing initial data is not guessed.

Optional `program_only` includes selected new program helpers as `Program/Tags/Tag` dependencies. `requiredTags.controllerCreateBeforeImport` remains a separate controller-parameter creation list; `bundledProgramDependencies` identifies what the routine L5X includes. It never includes controller definitions or baseline-existing tag values. Verify bundled helpers are still absent in the actual destination; otherwise refresh/regenerate without those definitions or use tag-free mode. UDT/AOI/alias/indirect dependency closure is not compiler-verified. This profile excludes protected/safety and other routine formats.

User-reported fatal native failures have involved both controller-containing and program-only generated routine files. Supported dependency syntax, package checks and acceptance of a particular native file/version are different evidence. Program-only is not a verified fix. Retain both reports without generalizing a root cause or replaying a customer import. Neither preparation mode establishes native acceptance.

Save `routine`, `prerequisites` and `package` artifacts to new paths. The ZIP contains routine.l5x, prerequisites.json and README.txt. Limits are 128 explicit prerequisites, 4 MiB routine XML and 2 MiB prerequisite JSON. Source snapshots and existing saved values are not modified.

For a separately authorized import, load the online-edit guide. Plan with the routine artifact ID/hash, `importKind:"routine"`, `routinePackagingMode` equal to the chosen mode, and the matching saved ACD/target. Program-only planning additionally requires `routineTagBaseline` with the pinned baseline project ID/hash. Use the parent program XPath plus exact routine targetName for full replacement. For the requested create-first/full-routine-finalize sequence, select `workflow:"finalize_during_import"` only after separate prerequisites have been created/verified. SDK FinalizeEdits provides no separate test interval. Verify native readback, rung/line counts, edit state and saved values; keep all observations pending until actually witnessed or reported.
