## RLL branch preflight

All four preservation/integrity profiles include `rll-native-branch-depth` and `rll-duplicate-series-predicates`. The pinned `logix5000-pm008j` structural profile uses the six nested branch levels documented in [1756-PM008J-EN-P, July 2022, page 12](https://literature.rockwellautomation.com/idc/groups/literature/documents/pm/1756-pm008_-en-p.pdf). It counts bracket and BST/NXB/BND control branches outside instruction parentheses. Array/member indexing and operand literals never count; extra parallel legs do not add nesting. The renderer's separate 16-level resource budget is not a native limit.

Seven/eight-level wrappers fail, including inherited findings and comparison of identical files. Expected native differences cannot waive depth/grammar failures. Findings retain exact source locations and rung hashes; corrected baseline findings remain visible as resolved. Rung/routine import preparation and routine import packages reject excessive depth before producing a native request.

Exact identical XIC/XIO and comparison predicates repeated within a contiguous series of supported predicates produce nonblocking `warning` findings and per-check `warnings` counts. Branch boundaries, outputs, calls and unknown/stateful instructions interrupt these paths. Warnings never remove predicates or claim scan equivalence. Unsupported/malformed/over-budget text stays explicit. Structured text, opaque routines, native compilation, scheduling, motion and runtime acceptance are outside this preflight. Generated tests cover readable program/AOI rungs, seven/eight-level wrappers, arrays/quoted branch tokens, parallel legs, repeated continuation predicates, inherited/resolved findings, waiver rejection and import rejection without SDK jobs.

## Selector refactor preview

`studio_selector_refactor_preview` and `POST /api/projects/{id}/logic/selector-refactor-preview` share a read-only Core operation. **Diagnostics & workflows → Selector refactor preview** opens the same operation editor in the GUI. Supply `expectedSha256`, an exact program `routineXPath`, a zero-based `rungIndex` and a fresh `routeTagPrefix` (1..24 identifier characters). The report pins the source snapshot and original rung hash, a deterministic review hash, proposed program-scope BOOL declarations, original MOV operands/order and every proposed rung. It creates no project revision, artifact, tags or native job; there is no automatic apply operation.

Supported selectors contain static BOOL XIC/XIO and DINT comparison predicates, DINT MOVs and one final top-level BOOL OTE. Direct saved tags, aliases, declared UDT members, fixed array elements and DINT bit contacts are resolved conservatively. Each original MOV gets a current OTE summary immediately before its unchanged write. Later MOVs retain their priority, and a downstream continuation predicate never retroactively suppresses an earlier MOV. Final setup combines current route results with the remaining predicates. Exact repeated contacts are retained. Generated proposal rungs have at most one branch nesting level.

The preview rejects calls, jumps, stateful/unknown instructions, destination roots read by predicates (including aliases or shared arrays/structures), non-DINT MOVs, constants as destinations, dynamic indexes, ambiguous/missing declarations, existing helper names, safety programs, AOI bodies, active online-edit rungs and setup paths bypassing every MOV. Limits are 32 writes, 128 expanded paths/predicates per path, existing 256-node/64-KiB rung budgets and a 2-MiB report. Unsupported input returns an error without a partial proposal.

Generated tests compare all 16 decision/continuation combinations against an independent small interpreter with stable Boolean inputs. They retain write traces and retry priority, stale-true helper resets, false continuation after an earlier MOV, repeated continuation contacts, fixed array operands and seven/eight-level wrappers reduced to at most one level. Rejection cases exercise aliases, calls/jumps, dependencies, types, constants, stale hashes, collisions and expansion budgets. Core/schema tests and builds establish source behavior; GUI wiring is compiled. Native compile/import, scan timing/equivalence, asynchronous writers, external helper ownership, motion and runtime acceptance remain separate.

## Static AOI argument linkage

All four profiles include `direct-rll-aoi-argument-linkage-v1`. Calls to AOIs with public parameter metadata are checked in readable program/AOI RLL routines. Each instance and supported scalar argument is resolved in the caller scope. Program locals shadow controller tags; alias chains resolve in their declaration scope. Declared UDT members, fixed array elements and integer bit members are walked through supplied metadata. Calls inside an AOI use that AOI's parameters/local tags and do not fall back to controller globals. Exact argument locations and original rung hashes bind new/inherited/resolved findings.

Instance type and scalar InOut STRING/UDT type identities must match. Output and nonconstant InOut references require a nonconstant declaration; a constant InOut parameter permits a constant reference. Constants/literals cannot stand in for InOut/output tag references. Required-only and full-visible parameter layouts follow declaration order, include every InOut parameter and exclude built-in EnableIn/EnableOut operands. Omitted optional parameters do not become missing-tag errors. Unrecognized intermediate layouts are unsupported. The [AOI manual](https://literature.rockwellautomation.com/idc/groups/literature/documents/pm/1756-pm010_-en-p.pdf) describes parameter usage, ordering, required/visible settings and constant InOut parameters; this check implements a bounded subset of those contracts.

Missing declarations/members, cyclic/dangling aliases, wrong exact types and missing required arguments fail, including inherited failures. Expected native differences cannot waive linkage failures. Dynamic indexes/expressions, array/MODULE parameter bindings, unavailable or ambiguous metadata, hidden members and implicit numeric conversions remain explicit unsupported findings. Simple atomic Input literals have bounded type/range handling. Unrecognized instructions, all ST/FBD calls, protected-code semantics, native compilation and complete cross-routine binding remain outside this check.

Generated fixtures cover eight calls with eleven missing local-alias arguments each (88 failures), an alias-only correction resolving all 88 with unchanged executable text, Input/InOut root/member checks, STRING/UDT exact types, arrays, optional layouts, scope shadowing, alias cycles, constant references, AOI-body encapsulation, unsupported conversions/metadata, inherited failures and waiver rejection. Tests preserve source bytes/revisions and create no SDK jobs. This vendor check does not modify a separately installed GM toolkit `plc_validate.py`; a GM workflow must explicitly consume this validation report as additional evidence. A model pass remains separate from native Studio Verify/build and runtime acceptance.

## Timer ownership audit

The separate `studio_timer_ownership_audit` result groups direct RLL TON/TOF/RTO instructions by resolved saved TIMER storage. Same local names in different programs stay distinct. Alias chains use declaration scope even when a caller shadows a controller name; UDT members and fixed multidimensional array indexes are canonicalized from metadata. Leading-zero/case differences do not create fictional new timer storage. RES and other consumers are references, not additional timer instruction owners. Direct JSR/AOI calls and structural prefixes are separate observations; opposite gates never suppress duplicate ownership findings. Repeated callers of a single timer instruction do not duplicate that instruction's ownership row.

AOI definition-local IDs describe templates, not globally shared physical timer instances. Exactly two local owners in Logic and enabled EnableInFalse are classified as a documented scan-mode exception; absent/ambiguous enable metadata remains unsupported. Other repeated instructions remain flagged. Reusing an AOI instance at several calls produces a separate warning. InOut parameter storage, nested caller aliasing and external/indirect invocation remain incomplete coverage. The original/library bodies are never edited.

The companion reference-rename preview binds the exact source hash, audit hash and owner ID. It lists every resolved matching RLL producer/consumer token and proposes a fresh private program TIMER for explicit same-program routine scopes. Selected references include EN/DN/TT/PRE/ACC, their supported bits, RES and reads inside arithmetic/index expressions; visible references outside the scope retain original storage. Existing controller-base rename previews also retain producer and member/reset references. Aliases used by the selected copy are redirected at the use sites, leaving alias declarations and original consumers untouched. Any remaining unknown selected effects, unresolved possible timer users or multiple selected owners block review. No tag/project/artifact mutation or native execution occurs.

Generated fixtures cover original/copy State.ManIntervention/MsgDelay and axis HMI timeout members, opposite JSR gates, controller aliases/chains, program shadowing, distinct program-local timers, canonical array/member addresses, one owner reached by several callers, AOI scan-mode exceptions/instance warnings, all paired fields/reset/expression/index references, original-library/source byte preservation, hashes, collisions and blocked mixed scopes. Core/schema tests and service/desktop compilation establish source behavior; no GUI/native/controller execution is claimed.

Coverage explicitly lists ST/FBD/other routine types, missing/opaque/protected AOI bodies and unknown call targets. Dynamic indexes, unsupported TIMER_T storage, unavailable/ambiguous/hidden member metadata and malformed/over-budget source do not produce invented identities. Every report has `completeScan=false`; a bounded pass means only the supported direct RLL inventory. It does not prove native compilation, complete scan/caller uniqueness, concurrent/external writes, scan timing, motion/safety or runtime acceptance. Limits: 64-KiB rungs and existing parser budgets, 16 MiB executable text, 20000 audit records, 8-MiB responses and 32 explicit consumer routines per preview. Budget failures return no partial report. The generic preservation profiles do not automatically run this separate audit.
